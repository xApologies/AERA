# AERA Enchanting — persistent object-identity engineering

**Status:** author-approved working framework checkpoint, 2026-10-13.
**Scope:** reusable AERA L1/L2 mechanics; not an MK231 plot or spell catalogue.

**Enchanting** is the **author-level term** for modifying an object's local Genesis-field geometry and persistent identity/inheritance so the object has an altered admissible property or functional system. The [locked lexicon](../LANGUAGE/AENITH_AINETH_AIN.md) names **Aineth** as the process, **Ain** as an individual persistent enchantment, and **Aenith** as an object possessing one or more Ain. The item remains the same identifiable object unless a particular transformation explicitly changes that identity.

**Persistence hard rule:** Once the object's Genesis identity is successfully altered, **the modification persists**. An activated effect, energy reserve or conduit can be unavailable, exhausted or disengaged without deleting the enchantment itself. Distinguish an intrinsic property from the energy required to perform a continuing effect.

**Two fabrication methods:**
1. **Prepared sigil / miniature Binding Circle:** put target at an appropriate anchor point; provide the designed Genesis crystals, dust, `vaen` and other compatible inputs; activate the sigil; consume designated inputs; select and resolve the intended identity modification. Standardized, reproducible, material-intensive. One activation + one prepared resource group per **coherent enchantment system**; a complex flaming-edge system can be one enchantment even if internally multicomponent.
2. **Direct Architect modification:** expert consciously constructs/holds the item's local Genesis manifold and resolves the alteration through direct Transduction. No inherent requirement for the same specialized *consumable* ingredients; still requires energy, effort, expertise, admissibility and time. Permits bespoke geometry beyond available standardized templates. Not effortless or free.

These methods can yield the **same persistent identity modification**. Do not treat sigil Binding as the only possible way to enchant or claim Architects are always incapable of standard production.

**Four configuration options**, which **may be combined**:
- Intrinsic property (permanent mass reduction, etc.).
- Activated property (touch/energy input, hilt sigil, etc.; effect can turn on/off).
- Finite reservoir (energy drawn from **either** a Red-through-Violet Genesis crystal **or** a charged Genesis Diamond; not only a diamond; not necessarily embedded).
- Basin conduit (Genesis crystals may serve as chromatic connection/anchor structures, e.g. R/O/G for a fictional flaming edge).

Optional material fatigue/stress/cooldown is **author-configurable**, not a mandatory law and not biological fatigue by default.

See other files for mechanism, energy source distinctions, and guardrails.
